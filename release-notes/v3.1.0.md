# v3.1.0

Muqun can now work with several coding agents on the same computer. OpenCode, DeepSeek and T3 Code appear side by side, each with its own launch tile, sessions and workbench.

## What's new

- **Several agents per gateway.** A gateway can attach OpenCode, DeepSeek Harness and T3 Code at once. Every session belongs to one agent, and the App addresses that agent explicitly, so a session always goes back to the agent that started it. If more than one agent is ready, starting a new session asks which one.
- **Launch tiles built from what the gateway advertises.** Home shows one tile per agent the gateway reports, in the gateway's order with the agent you used last first, each with its own mark. An agent that is not installed or not running says so on its tile and opens a start guide written for that agent. With more than three agents, the rest collapse into a "More agents" sheet. Terminal tiles name the backend when a gateway lists more than one.
- **Continue names the agent.** Continue rows, the server card, the widget and the offline and empty-state messages say which agent they mean instead of always saying OpenCode. Existing OpenCode recents and settings carry over.
- **One live connection for agent events.** The App keeps a single WebSocket per gateway for agent events, so approvals and status changes for every session arrive together instead of only for the one you have open. It reconnects and catches up on its own, and falls back to the previous per-session stream if the WebSocket cannot be used.
- **A workbench scoped to its agent.** Modes, the model picker, slash commands, skills, attachments, undo, compaction, background runs and the inbox appear only when the agent supports them. The model picker groups models by provider and greys out providers that are not signed in on the host. Errors are reported as the agent refusing a request, not as the service being offline.
- **A tablet Home built around the theme.** On a Pad the Home screen is a two-page spread: the theme's cover and title fill the left, and the right column holds New session, Continue and Connections, all on one screen. The navigation rail appears only inside the workspace. Pair a server, SSH and Settings sit in the Home toolbar.
- **A tablet Home that looks finished before any theme is installed.** Without a theme pack the cover column now carries the Muqun name, set as large as the column allows over a quiet circuit-line texture, instead of an empty grey page. Before the first server is paired, the "Pair your first server" card sits under the name in the middle of the cover rather than at its foot. Theme packs with a cover keep their layout unchanged.
- **Switching inside the Pad workspace stays put.** Tapping a Continue row or a terminal in the rail swaps only the right-hand column; the rail and the terminal you were in stay mounted. Agent sessions open in the same column with their own New session and Stop control. Shrinking the window to phone width hands the session to the phone layout and back.
- **Undo on agents that cannot stage it.** T3 Code rolls a whole turn back in one step, so "Undo to here" asks for confirmation and then applies it, instead of failing. "Move to worktree" and the worktree badge appear only for agents that support worktrees.
- **Setup guides that match the host.** An agent the gateway can see but has not been given credentials for shows a "Needs setup" tile with the exact command to run (for T3 Code, `t3 pair`). The OpenCode and DeepSeek guides name the commands the gateway actually uses.
- **Terminals you just used stay near the top of Continue.** The pane you are working in is refreshed in Continue every 30 seconds while you use it, and a pane in a session with more than 24 panes is no longer mistaken for a closed one.
- **Pad fixes.** On a tablet, Continue rows in the Pad workspace now open their terminal panes instead of doing nothing. Opening an agent session no longer risks a "Maximum update depth exceeded" crash.
- **A new graphics renderer.** The terminal, the launch scene, Home artwork, ambient effects and theme transitions now draw with React Native Skia 3 on its Graphite backend, which draws with Vulkan instead of OpenGL on Android.
- **The opening ends by coming apart.** When the theme's opening hands over to Home, the picture breaks into small tiles that drift away, sweeping from left to right, and Home arrives through the gaps they leave, instead of the opening fading out. With Reduce Motion on, the opening still ends with a plain fade.
- **Theme and font changes have their own transitions.** Changing the theme or switching between light and dark spreads the new look out from the row you tapped like a ripple on water, with a few rings that settle flat. Changing the font sends a scan band up and down from the row you tapped, and the new font appears behind it as the old page breaks up into small blocks. With Reduce Motion on, both still use a plain fade.
- **Interface background opacity reaches every surface.** Sheets, notifications, notices, theme tag chips and agent form fields now follow the theme's "Interface background opacity" setting. At the default of 1 a sheet is fully opaque; lowering the setting lets the wallpaper show through.
- **A narrower line-number gutter in diffs.** In both Changes sheets and in transcript diffs, the line-number gutter is only as wide as the numbers need, and an untracked or deleted file shows a single number column, so code starts much closer to the left edge on a phone. Long lines still stay on one line and pan sideways, now with a scroll indicator whenever there is more to the right.
- **One Changes sheet for terminals and agent sessions.** A terminal pane's Changes sheet is now the same sheet as an agent session's: the changed files as a folder tree with a file count and line totals, "Uncommitted changes" or "Compared with" the branch's base, a file's patch loaded when you open it with "Show more context", and Discard on a file's "…" menu. The All / Staged / Unstaged tabs are gone. File and folder names in the tree stay on one line and are shortened in the middle, so the extension stays visible, and deep folders stop indenting after three levels. Comparing with the base and Discard in a terminal need a Gateway that advertises `pane_vcs_files`; on an older Gateway the terminal sheet shows the same tree of uncommitted changes without them.
- **Work sheets fill the screen on a Pad.** On a tablet, Changes (for a terminal pane or an agent session), Files, the agent session tree and a subagent's transcript, Browse themes and Pair server now open full-screen instead of as a card in the middle of the screen, with a close button in the top corner (Android's Back also closes them). Quick pickers -- model, mode, agent, workspace, language, font and the rest -- still open as sheets. Phones are unchanged.
- **A full on-screen keyboard on the Pad, and the chords a terminal actually takes.** On a tablet the on-screen keyboard is a whole keyboard: a function-key strip you can hide, a number row, `[ ] \ ; '` where a hand expects them, sticky ctrl, alt and shift (double-tap to lock), and Home/End/Page Up/Page Down over the arrow keys. Ctrl+Enter, Shift+Enter, Ctrl+arrows, Alt+letters and F-keys now reach a terminal whose Gateway says it can deliver them; a key it cannot deliver is drawn muted and says so when pressed, instead of doing nothing. When the program in a terminal has not turned on extended keys, arming ctrl, alt or shift dims the keys that combination cannot reach and says why for as long as the modifier is held.
- **Opened files are readable on any theme.** A file opened from the Files sheet now sits on the same frosted background as every other sheet, so a document, source file, JSON, CSV or a file's details is no longer drawn straight over the theme's wallpaper, and it follows the "Interface background opacity" setting like the sheets do. Every kind now keeps the sheet's left and right margins, and very large files are shown in the same code panel as smaller ones. Code still stays on one line and pans sideways. Images still open on a black background.
- **Type a path with `~`, and the Switch project sheet completes it.** In an agent session's Switch project sheet, typing `~/` or `/` now lists the folders that start with what you have typed (up to 20, with a note to keep typing when there are more), and each row has a small "go into" button that fills the field with that folder so you can keep descending; tapping the row opens it. A `~` path is opened as the absolute folder the Gateway names, so it is the same project as its full path. Gateway 0.13.1 expands `~` and filters the list on its side; on an older Gateway the App narrows the list itself, and a `~` path shows a hint to type the full path instead.
- **The Changes sheet names the branch.** Under the title, a quiet line shows the repository's branch, with how far it is ahead of or behind its upstream when that is not zero; a detached checkout shows "detached at" its short commit, and a repository with no commits yet says so. Agent sessions and terminal panes alike; on a Gateway older than 0.13.1 a terminal pane still shows the branch from its status call, and an agent session shows no line.
- **Cover Courier is the default theme.** Until you install a theme or pick a colour pack, the App wears Cover Courier, which now ships inside the App: the first launch already plays its opening, and Home shows its courier artwork and paper wallpaper, in light and dark. Install a theme or pick a pack and your choice takes over; remove all of your themes without a pack picked, or choose Cover Courier in the theme picker, and it comes back. It is listed in the picker as the default and cannot be removed.

## Fixes

- **A gateway with no terminal backend running no longer leaves the terminal on its loading logo.** Pairing a computer where tmux is installed but no tmux server is running (or Herdr is not started) used to show the loading logo forever. The terminal now says it is unavailable, explains what to start, and lists the gateway's backends with their state; it picks the terminal up as soon as the backend starts. "New terminal" on Home gives the same explanation instead of only saying no session is available. Agent sessions keep working either way.
- **The "Open in your browser" sheet fits its content and closes from its grabber.** On some phones the Open button ran off the bottom of the sheet and dragging the grabber did nothing. The sheet is now sized like every other picker, with a gap under the button, and dragging the grabber closes it even while the port field has focus. Across all sheets, a field's underline is now visible on light paper themes, and a disabled button is drawn quietly instead of as a dimmed primary button.
- **A terminal's chat view no longer repeats an earlier screen or flickers while a program prints.** When a full-screen program such as Claude Code redrew its status region, the Gateway could write the same screen down twice and the chat view showed an older screen under newer messages; the App now shows such a screen once (the Gateway fix lands in Gateway 0.13.1). Chat rows also kept being renumbered as output scrolled past the Gateway's window, which re-created every row on every refresh; rows now keep their identity, so the list no longer blinks. The chat view also used to re-read the transcript only when the pane's revision changed, which on Herdr follows the title and status rather than output, so it could keep showing an old snapshot of the screen while the terminal moved on; it now re-reads whenever new output arrives. On Android the terminal page's header has a frosted ground like the sheets, so text scrolling under it no longer reads through the title.
- **A full-screen program no longer makes the terminal flash.** When a program such as a TUI painted about half the screen in its own colour, the pane adopted that colour as its background on one refresh and dropped it on the next, flipping the whole pane, and every refresh while adopted redrew every block. Adoption now has a margin on both sides, the pane's look keeps its identity while the colours stay the same, and the canvas kind never changes during a pane's life. For diagnosis, `EXPO_PUBLIC_TERMINAL_GRAPHITE_CANVAS=0` switches the terminal back to the picture view and `EXPO_PUBLIC_TERMINAL_TRACE=1` logs the blocks recorded per refresh.
- **The agent session and the terminal share one header.** An agent session used to draw its own taller header with a dead gap under it; it now uses the terminal's row of floating pills (back, title with the status dot, New or Stop), with the transcript scrolling under the same frosted fade, and the first card starting directly under the pills. The Pad's agent column follows the same geometry.
- **iPhone and iPad details.** An expanded thought no longer collapses into a narrow column the width of its "Thought" button. The "Open in your browser" sheet sits flush on the keyboard instead of leaving a strip of the page showing beneath it, and the duplicate Done bar is gone (the number pad's own Go key remains). The iPad sidebar no longer marks a server offline when only its tmux server is missing.
- **The font scan plays on iPhone and iPad even when the screen is slow to photograph.** Changing the font while its sheet is open used to swap the typeface in a single frame on a busy device. It now falls back to the same scan over a sheet of the theme's paper.
- **A server no longer reads "Not connected" for a moment after a theme change.** When its last check had gone stale, re-skinning the screen showed the current server as not connected until the next check answered; the previous answer now stays until the new one arrives.
- **A refused key combination releases ctrl, alt and shift.** Pressing a combination the terminal cannot take, such as Ctrl+Enter on a tmux without extended keys, now uses up a one-tap modifier just as a sent key does, so the next letter is typed as a letter rather than as a control character. A modifier locked with a double tap stays locked. Dimmed keys can be pressed while a modifier is held, and say why nothing was sent.
- **Every file's "…" button in the Changes sheet is announced to VoiceOver.** On iPhone and iPad some rows' action buttons, including untracked files in a terminal's Changes sheet, had no label for screen readers.
- **The terminal's composer appears with the terminal.** Opening a server that Home had already loaded drew the terminal at once but held the composer and key row back until the screen's own first refresh answered, which on a busy computer took several seconds.
- **A refused key combination says how to fix it.** When the Gateway refuses a combination such as Ctrl+Enter, the hint under "This terminal can't send ⌃↵" now repeats the Gateway's own explanation, which on tmux names the command to run (`tmux set -s extended-keys on`). Getting Ctrl+Enter through tmux also needs `extended-keys-format csi-u`.

## Requirements

- **Gateway:** a Gateway that advertises the `multi_agent` and `ws_events` capabilities and reports API 1.9.0 or newer (Gateway 0.13.0 or newer). Update the Gateway before relying on multi-agent features.
- **Older Gateways: OpenCode sessions still open, but update soon.** Without those capabilities the App stays in single-agent mode against OpenCode and uses the per-session event stream. Gateway 0.12 and older still name modes and the mode switch under the old `agents` fields, which this App no longer reads, so on those gateways the mode list is empty and switching modes fails until the Gateway is updated. Where a feature needs a newer Gateway, the App says so.
- **Herdr:** unchanged. Terminal integration needs the Herdr versions the Gateway release notes list.
- **Android:** Android 8.0 (API 26) or newer. Phones on Android 7 can no longer install or update the App.

## Upgrade

- Update the Gateway first if you want the new agents, then update the App. Existing pairings, saved servers and OpenCode history are kept; no re-pairing is needed.
- This release adds a native WebSocket module, so it is a full app update, not an over-the-air update. Older installed binaries keep using the per-session stream.

## Installing the APK (Android)

`muqun.apk` is attached to this release together with `muqun.apk.sha256`. It targets ARM64 devices and uses the package name `dev.osuki.muqun`.

1. Download `muqun.apk` and `muqun.apk.sha256` from this release.
2. Verify the download: `sha256sum -c muqun.apk.sha256` (Linux) or `shasum -a 256 -c muqun.apk.sha256` (macOS).
3. Open the APK on the phone and allow installs from your browser or file manager when Android asks. Confirm the install.
4. Open Muqun and pair with your Gateway as usual.

**Signing.** The APK is built from this tag with the project's existing Expo-managed signing key. It has not been verified that this key is the one Google Play uses to sign the store version, so an APK cannot be assumed to update a Play-installed copy in place. If Android refuses the update, uninstall the Play version first (this removes the App's saved servers and keys from the phone) or keep using the store build. Play and App Store users should simply update from the store.
