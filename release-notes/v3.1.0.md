# v3.1.0

Muqun can now work with several coding agents on the same computer. OpenCode, DeepSeek and T3 Code appear side by side, each with its own launch tile, sessions and workbench.

## What's new

- **Several agents per gateway.** A gateway can attach OpenCode, DeepSeek Harness and T3 Code at once. Every session belongs to one agent, and the App addresses that agent explicitly, so a session always goes back to the agent that started it. If more than one agent is ready, starting a new session asks which one.
- **Launch tiles built from what the gateway advertises.** Home shows one tile per agent the gateway reports, in the gateway's order with the agent you used last first, each with its own mark. An agent that is not installed or not running says so on its tile and opens a start guide written for that agent. With more than three agents, the rest collapse into a "More agents" sheet. Terminal tiles name the backend when a gateway lists more than one.
- **Continue names the agent.** Continue rows, the server card, the widget and the offline and empty-state messages say which agent they mean instead of always saying OpenCode. Existing OpenCode recents and settings carry over.
- **One live connection for agent events.** The App keeps a single WebSocket per gateway for agent events, so approvals and status changes for every session arrive together instead of only for the one you have open. It reconnects and catches up on its own, and falls back to the previous per-session stream if the WebSocket cannot be used.
- **A workbench scoped to its agent.** Modes, the model picker, slash commands, skills, attachments, undo, compaction, background runs and the inbox appear only when the agent supports them. The model picker groups models by provider and greys out providers that are not signed in on the host. Errors are reported as the agent refusing a request, not as the service being offline.
- **A tablet Home built around the theme.** On a Pad the Home screen is a two-page spread: the theme's cover and title fill the left, and the right column holds New session, Continue and Connections, all on one screen. The navigation rail appears only inside the workspace. Pair a server, SSH and Settings sit in the Home toolbar.
- **Switching inside the Pad workspace stays put.** Tapping a Continue row or a terminal in the rail swaps only the right-hand column; the rail and the terminal you were in stay mounted. Agent sessions open in the same column with their own New session and Stop control. Shrinking the window to phone width hands the session to the phone layout and back.
- **Undo on agents that cannot stage it.** T3 Code rolls a whole turn back in one step, so "Undo to here" asks for confirmation and then applies it, instead of failing. "Move to worktree" and the worktree badge appear only for agents that support worktrees.
- **Setup guides that match the host.** An agent the gateway can see but has not been given credentials for shows a "Needs setup" tile with the exact command to run (for T3 Code, `t3 pair`). The OpenCode and DeepSeek guides name the commands the gateway actually uses.
- **Terminals you just used stay near the top of Continue.** The pane you are working in is refreshed in Continue every 30 seconds while you use it, and a pane in a session with more than 24 panes is no longer mistaken for a closed one.
- **Pad fixes.** On a tablet, Continue rows in the Pad workspace now open their terminal panes instead of doing nothing. Opening an agent session no longer risks a "Maximum update depth exceeded" crash.
- **A new graphics renderer.** The terminal, the launch scene, Home artwork, ambient effects and theme transitions now draw with React Native Skia 3 on its Graphite backend, which draws with Vulkan instead of OpenGL on Android.
- **The opening ends by coming apart.** When the theme's opening hands over to Home, the picture breaks into small tiles that drift away, sweeping from left to right, and Home arrives through the gaps they leave, instead of the opening fading out. With Reduce Motion on, the opening still ends with a plain fade.
- **Interface background opacity reaches every surface.** Sheets, notifications, notices, theme tag chips and agent form fields now follow the theme's "Interface background opacity" setting. At the default of 1 a sheet is fully opaque; lowering the setting lets the wallpaper show through, down to a floor that keeps text readable.
- **A narrower line-number gutter in diffs.** In both Changes sheets and in transcript diffs, the line-number gutter is only as wide as the numbers need, and an untracked or deleted file shows a single number column, so code starts much closer to the left edge on a phone. Long lines still stay on one line and pan sideways, now with a scroll indicator whenever there is more to the right.
- **One Changes sheet for terminals and agent sessions.** A terminal pane's Changes sheet is now the same sheet as an agent session's: the changed files as a folder tree with a file count and line totals, "Uncommitted changes" or "Compared with" the branch's base, a file's patch loaded when you open it with "Show more context", and Discard on a file's "…" menu. The All / Staged / Unstaged tabs are gone. File and folder names in the tree stay on one line and are shortened in the middle, so the extension stays visible, and deep folders stop indenting after three levels. Comparing with the base and Discard in a terminal need a Gateway that advertises `pane_vcs_files`; on an older Gateway the terminal sheet shows the same tree of uncommitted changes without them.
- **A full on-screen keyboard on the Pad, and the chords a terminal actually takes.** On a tablet the on-screen keyboard is a whole keyboard: a function-key strip you can hide, a number row, `[ ] \ ; '` where a hand expects them, sticky ctrl, alt and shift (double-tap to lock), and Home/End/Page Up/Page Down over the arrow keys. Ctrl+Enter, Shift+Enter, Ctrl+arrows, Alt+letters and F-keys now reach a terminal whose Gateway says it can deliver them; a key it cannot deliver is drawn muted and says so when pressed, instead of doing nothing. When the program in a terminal has not turned on extended keys, arming ctrl, alt or shift dims the keys that combination cannot reach and says why for as long as the modifier is held.

## Requirements

- **Gateway:** a Gateway that advertises the `multi_agent` and `ws_events` capabilities and reports API 1.9.0 or newer (Gateway 0.13.0 or newer). Update the Gateway before relying on multi-agent features.
- **Older Gateways: OpenCode sessions still open, but update soon.** Without those capabilities the App stays in single-agent mode against OpenCode and uses the per-session event stream. Gateway 0.12 and older still name modes and the mode switch under the old `agents` fields, which this App no longer reads, so on those gateways the mode list is empty and switching modes fails until the Gateway is updated. Where a feature needs a newer Gateway, the App says so.
- **Herdr:** unchanged. Terminal integration needs the Herdr versions the Gateway release notes list.
- **Android:** Android 8.0 (API 26) or newer. Phones on Android 7 can no longer install or update the App.

## Upgrade

- Update the Gateway first if you want the new agents, then update the App. Existing pairings, saved servers and OpenCode history are kept; no re-pairing is needed.
- This release adds a native WebSocket module, so it is a full app update, not an over-the-air update. Older installed binaries keep using the per-session stream.

## Installing the APK (Android)

`muqun.apk` is attached to this release together with `muqun.apk.sha256`. It targets ARM64 devices and uses the package name `dev.osuki.muqun`.

1. Download `muqun.apk` and `muqun.apk.sha256` from this release.
2. Verify the download: `sha256sum -c muqun.apk.sha256` (Linux) or `shasum -a 256 -c muqun.apk.sha256` (macOS).
3. Open the APK on the phone and allow installs from your browser or file manager when Android asks. Confirm the install.
4. Open Muqun and pair with your Gateway as usual.

**Signing.** The APK is built from this tag with the project's existing Expo-managed signing key. It has not been verified that this key is the one Google Play uses to sign the store version, so an APK cannot be assumed to update a Play-installed copy in place. If Android refuses the update, uninstall the Play version first (this removes the App's saved servers and keys from the phone) or keep using the store build. Play and App Store users should simply update from the store.
