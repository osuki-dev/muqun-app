# v4.0.0

Muqun 4.0 brings tasks, conversations, terminal work and Git into one workspace
for your paired computers. This is the next native release candidate; store
acceptance and backend integration checks are required before public release.

## Agents and connected workspaces

- **Several agents on one computer.** Codex, OpenCode, DeepSeek Harness and T3 Code
  have their own launch tiles, sessions and workbench. Home shows the agents
  the Gateway advertises, with setup guidance for unavailable agents. Existing
  OpenCode sessions and saved settings carry over.
- **Codex conversations in the workspace.** Read messages, image attachments,
  shell results, child agents and token usage, and respond to supported questions
  and approvals. Gateway uses the official Codex app-server protocol; available
  controls follow the selected session's runtime and advertised capabilities.
  A terminal-owned session is not presented as a controllable native session
  until Codex accepts the connection.
- **Live activity across conversations.** A shared Gateway WebSocket carries
  agent events, approvals and status changes. Supported older Gateways retain
  the per-session event stream. Models, modes and other controls follow the
  selected agent's advertised capabilities.
- **A workspace for phones and tablets.** Tablet Home pairs theme artwork with
  work and connections; terminal and agent work stay in the workspace column.
  Detailed work sheets use the tablet's screen, while quick choices remain
  compact pickers. Classic and Editorial Home share recent-session actions.
- **More complete terminal controls.** The tablet keyboard includes function
  keys, navigation keys and sticky modifiers. Unsupported key combinations
  explain the backend requirement instead of appearing to succeed.
- **Terminals open at once.** A pane shows its last screen as soon as you tap
  it, and going back to Home no longer stalls while conversations reload. A
  narrow host pane fills the width, and streaming output no longer jumps or
  flashes while you read above it.

## Work from Home

- **One subtitle per linked conversation.** Stage prefers conversation activity
  over its associated terminal output, while keeping separate conversations and
  independent terminals visible. Subtitle taps retain the originating session.
- **Keep talking to the same conversation.** Home replies to the conversation
  it started; long-press a Stage card or choose Reply from Home to pick another.
  The composer names the destination while you type, and task options show a
  Reply to row with New conversation to let it go.
- **A reply drawer above the composer.** The Conversation button opens the
  conversation's transcript, with its questions and approvals, or the live
  terminal, without leaving Home. Terminal panes get the key row there too. The
  drawer forms out of ash and returns to the dock, keeps its scrolling to
  itself, and uses the same theme wallpaper as the full workspace.
- **A living Stage.** Stage builds a 3D world from the theme's own art, with
  computers as glowing cores and their agents in orbit. The working agent's
  progress reads as a subtitle on a theme plate; tap it to open the agent, or
  double-tap the art to start a new task. Stage draws only when something
  moves and steps down a quality rung when frames start to drop.
- **Start work from the Home composer.** Choose a computer, agent, model, mode
  and project folder, attach files, and send a goal. Home opens the resulting
  conversation or terminal directly. A send whose delivery is uncertain stays
  visible for review instead of silently submitting the same goal again.
- **See the work that needs you.** Computer cards show active tasks, progress,
  requests for a decision and recent work. Child tasks keep their parent's work
  visible while they are running. Remembered activity is labelled separately
  from the computer's current connection state.
- **Manage tasks and sessions in place.** Open saved command results, remove
  task rows with inline confirmation, and use the scoped session deletion menus.
  Closed terminals no longer linger as active work on Home.
- **A clearer tablet workspace.** The Home composer and current theme artwork
  fit alongside the work. Native navigation keeps Home and conversations in
  their usual navigation stack, and long active pane titles reveal their start.

## Voice, media and Git

- **Dictate into the draft.** Hold Send to record, then stop the recording and
  review the transcript without leaving the composer. Configure an
  OpenAI-compatible file transcription endpoint or a compatible realtime
  transcription endpoint in Voice to text. Dictation inserts text without
  sending it; cancelling or leaving the recording discards it.
- **Read richer replies.** Native diagrams, inline audio previews, conversation
  media, PDF previews and saved files share the workspace. Open PDFs from Files
  or supported conversation attachments. Audio plays only after you choose Play,
  and stops when its preview closes or dictation starts. Streaming replies reveal
  content progressively while preserving your position when reading history.
- **The checkout at a glance.** The Git sheet's heading names the checkout and
  branch and says how much is uncommitted, with Open in Lazygit and Refresh
  beside it. Changed files are grouped as conflicts, staged, unstaged and
  untracked, and the comparison base is one tap away.
- **Browse linked worktrees.** When a repository has several checkouts, they
  appear as chips with the pane's own checkout first, and a long list says how
  many it shows. Other checkouts are read-only, and browsing them leaves the
  terminal in its current checkout.

## Appearance, storage and updates

- **Change themes smoothly.** A new theme cross-fades in, Stage artwork comes
  back after every theme change, and returning Home reuses the existing scene.
  A failed theme download, install, save or removal is reported as a message
  you can see wherever you are in the list.
- **A single Themes sheet.** Your themes, the built-in ones and the gallery
  share one scrolling sheet, and themes can draw the composer's Conversation
  button.
- **A refreshed native renderer.** Skia 3 uses Graphite, including Vulkan on
  Android, for terminal rendering, theme artwork and effects. Supported Apple
  displays retain wide-colour artwork. Reduced Motion keeps simple transitions.
- **Explore connected computers.** The computer map adds a 3D view of the
  connections reported by the Gateway. A new 4.0 introduction uses animated
  particles to introduce the workspace.
- **Keep your chosen appearance.** Cover Courier remains the built-in default;
  imported theme updates refresh the active theme, and Home's composer and tablet
  artwork follow the theme. Neon is the new default app icon, Classic joins Mecha
  and the other alternates, and the in-app brand mark follows your icon.
- **See what Muqun stores.** Storage breaks usage into app code, app data,
  updates and caches. Orphaned temporary files are cleaned at launch, automatic
  cleanup runs every ten days on new installs, and the Storage sheet opens
  tall enough to show every row.
- **Read update details before downloading.** Compatible JavaScript updates
  show what changed and the download size, in the app's language when provided,
  with an English fallback. Long notes scroll inside a dialog that keeps its
  shape. A ring follows the native transfer, and a verified download restarts
  the app. Choosing Later defers the prompt for the current launch; the next
  cold launch can offer it again.
- **Messages you have time to read.** Notifications stay up for five seconds,
  and warnings and errors stay longer.
- **More reliable terminal and conversation state.** Captured terminal history
  stays on a stable snapshot, startup restores workspace data, and send errors
  and agent questions remain readable. Computer settings focus on the
  capabilities needed for terminal and agent work.

## Compatibility and availability

- **Gateway:** update your Gateway for task, agent and Git capabilities. The app
  checks advertised capabilities and explains unavailable features; a version
  number alone does not establish support.
- **Multiple agents and shared events:** require `multi_agent` and `ws_events`.
  Older Gateways retain their available terminal and OpenCode paths; update
  the Gateway for current mode selection and other newer agent controls.
- **Agent assignment:** requires `agent_collaboration` and a connected Herdr
  0.9.0 or newer backend. Backend support and a real paired startup, follow-up
  and returned-output check remain release prerequisites. This candidate does
  not establish complete collaboration support on every backend. Ordinary
  terminal use remains available without that capability.
- **Android:** Android 8.0 (API 26) or newer.
- **iOS and iPadOS:** 16.4 or newer.
- **iPhone Duo:** supported on both displays. Controls stay clear of the side
  status column, and a half-typed Home message survives folding and unfolding.
- **Git worktrees:** require `git_worktrees`; Open in Lazygit requires
  `pane_lazygit`. Repositories with more than 128 linked checkouts need Gateway
  0.14.1-preview.7 or newer to list them.
- **Native runtime:** this release changes native audio, rendering and updater
  inputs and adds native PDF support. It requires a new store binary; a
  JavaScript update cannot supply missing native modules or change the installed
  app's marketing version.

## Upgrade

- Update the Gateway first, then install or update Muqun through Google Play on
  Android or the App Store on iOS. Existing pairings and saved settings are kept;
  no uninstall or re-pairing step is required.
- If you used the default app icon, you will see Neon after updating. Choose
  Classic in Settings > Appearance > App icon to bring it back; a previously
  chosen alternate is kept.
- Test builds are delivered as AAB uploads through Play internal testing and
  IPA uploads through TestFlight. Validate a production-channel candidate there
  before promoting that same build to the public store.
- Previously submitted test builds keep their original version and fingerprint.
  The 4.0.0 build receives a new native fingerprint and increasing build counter;
  subsequent OTA updates must match its platform and embedded update channel.
