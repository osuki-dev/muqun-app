# `@osuki-dev/ui` 2.0 migration notes

Inventory for moving Muqun from `@osuki-dev/ui` 1.1.0 (npm, `package.json`
`^1.1.0`) to 2.0.0. Written on `feat/ui-2.0` against the kit's
`feat/composition-theming-icons` branch at `46d2603` (package version
`2.0.0`, spec `docs/specs/v2-composition-theming-architecture.md`, status
"in active execution"). The kit's `main` is identical to the published 1.1.0
(`git log @osuki-dev/ui@1.1.0..main` is empty), so "1.x" below means both.

The library API may still move. Re-run the probe in "Method" before starting
and update this file if the picture changed.

## Summary

- **The theme layer does not change.** `packages/ui/src/index.ts`,
  `theme/types.ts`, `theme/typography.ts`, `theme/theme-provider.tsx`,
  `theme/motion.ts`, `theme/presets.ts`, `theme/create-theme.ts`, `fonts/` and
  `navigation/` are byte-identical between `main` and the branch.
  `theme/index.ts` only gains exports (the surface decorator, `withAlpha`,
  `readStringFill`, `withoutStringFill`).
- **No export the app uses is renamed or removed.** The one removal in the
  public surface is the `export * from "lucide-react-native"` re-export in
  `components/icon.tsx`; the app does not use it (its 100 Lucide imports come
  from `lucide-react-native` directly).
- **Type breakage is confined to one file.** Typechecking the app against the
  branch's source produces errors only in `src/components/themed-button.tsx`
  (7 errors, all from `ButtonProps.style` widening to `StyleProp<ViewStyle>`).
- **The real work is behavioural.** 2.0 adds a surface decorator and compound
  parts so the app's forks (`themed-button`, `themed-card`, `themed-tabs`,
  `themed-skeleton`, `themed-segmented-control`) can collapse onto the kit
  primitives. It also changes paint, border and clipping details of `Card`,
  `Button`, `Tabs`, `SegmentedControl`, `Tag` and `Icon`, and adds an Android
  trailing thin space to every kit `Text`, which collides with the app's own
  `HugSlack` in `src/components/text.tsx`.

## Method

The type picture comes from a throwaway tsconfig (kept outside the repo) that
extends the app's `tsconfig.json` and maps `@osuki-dev/ui` to
`/home/ryu/Work/kit/packages/ui/src/index.ts`. It also maps `react`,
`react-native` and the kit's peer packages to the app's `node_modules`, so both
sides see one copy of React Native's types:

```json
{
  "extends": "<app>/tsconfig.json",
  "compilerOptions": {
    "noEmit": true,
    "skipLibCheck": true,
    "paths": {
      "@/*": ["<app>/src/*"],
      "@osuki-dev/ui": ["<kit>/packages/ui/src/index.ts"],
      "react": ["<app>/node_modules/@types/react/index.d.ts"],
      "react/*": ["<app>/node_modules/@types/react/*"],
      "react-native": ["<app>/node_modules/react-native/types_generated/index.d.ts"],
      "react-native-reanimated": ["<app>/node_modules/react-native-reanimated"]
    }
  }
}
```

Without the peer mapping the probe reports about 45 false errors caused by the
kit's own React Native 0.86.2 typings. With it, 7 app errors remain (all in
`themed-button.tsx`), plus 22 errors inside the kit's own source. Those 22 come
from the app's React Native 0.88 typings: `TextLayoutEventData`,
`TextInputKeyPressEventData` and `TextInputContentSizeChangeEventData` are gone,
and ref and `measure` are typed differently. About half of them already exist in
1.1.0 (`text.tsx`, `otp-input.tsx`). The app does not see them when it consumes
the built `lib/*.d.ts` with `skipLibCheck`. Metro bundles `src/` through the
`react-native` export condition either way, so the kit should be typechecked
against React Native 0.88 before 2.0 is published.

## Asks for the kit before the app migrates

1. **`Text` hug slack.** Make it opt-in (or provide an app-level switch) and skip
   `selectable`, empty, and nested text. Otherwise the app must stop adding its
   own slack and accept (b) to (e) from the table. The app's rule (only for a
   reader font file, outermost only) is documented in `src/components/text.tsx`
   with on-device measurements.
2. **Nano icons.** Replace the `new Function` `safeRequire` with a static
   `require` inside `try`, as is already done for Lucide and `expo-image`.
3. **Typecheck against React Native 0.88.** See "Method".
4. Optional: keep `IconName` strict for Lucide names (a separate
   `LooseIconName` for theme or custom names) so tsc still catches typos.

## Migration plan (ordered)

Each step is one commit, with the AGENTS.md checks at the end of the batch and
a full device e2e at the batch's final head.

1. **Bump and link.** Point `@osuki-dev/ui` at 2.0.0 (the published tarball, or
   a `file:` / workspace link while it is unpublished; never commit a local
   path). Run `npx tsc --noEmit`: expect exactly the 7 `themed-button.tsx`
   errors.
2. **`themed-button.tsx` types.** Read the caller style through `StyleSheet.flatten`
   (as `themed-card.tsx` already does with `flattenStyle`) instead of
   `style?.x` and `...style`. tsc is clean at this point and the app should
   look identical apart from the kit's own paint changes. Do a device pass
   here to separate kit regressions from the refactor below.
3. **Mount the surface decorator.** Add `SurfaceDecoratorProvider` inside the
   `ThemeProvider` in `src/app/_layout.tsx` and in `CandidateThemeProvider`
   (`src/components/theme-candidate.tsx`, so theme previews get the candidate's
   opacity). `transformBackground` = `useSurfaceBackground()`.
   `renderDecoration` = `ThemeArtworkLayer` for slots present in the active
   manifest, with the same `safeArtworkOpacity` / `jointArtworkOpacity` limits
   the fork computes. Read the fill from `meta.baseColor`; the label colour is
   not in `SurfaceMeta` today, so either ask the kit to add `foreground`, or
   keep that computation in the app.
4. **Collapse the forks, one per commit.**
   - `themed-skeleton.tsx` becomes a re-export of `Skeleton`.
   - `themed-tabs.tsx` becomes a re-export of `Tabs` (the kit now paints per
     trigger).
   - `themed-card.tsx` keeps only the profile radius (`profile.chrome.card`) and
     the hairline border. Audit the 4 importers for children that relied on
     dark-mode clipping, and add `overflow: 'hidden'` where needed.
   - `themed-button.tsx` becomes `Button.Root` + `Button.Background` + the
     default parts, with only the profile radius and the transparent-label
     protection left in the app.
   - `Tag` call sites drop their `transparentFill` / `badgeTransparent` overrides.
5. **`Text`.** Depends on kit ask 1. If the kit makes the slack opt-in, leave
   `src/components/text.tsx` as it is. If it does not, remove the app's own
   slack, keep the `fontVariationSettings` weight layer, and re-verify the
   italic-overhang cases listed in that file's comment, `selectable` copy, and
   round badges.
6. **Icons.** No code change is required. Optionally adopt `IconProvider` for
   theme chrome icons (`chrome.back`, `chrome.send`, ...) if the theme pack
   work wants it. Measure a long list (session list, file mentions) in a
   Release build before and after, because of the extra wrapper `View` per icon.
7. **Validate.** `npx tsc --noEmit`, `bun run lint` (including
   `muqun/react-compiler` on every touched component), `bun run format:check`,
   `bun test src`, then `bash scripts/e2e.sh` on a QA device. Surfaces to
   eyeball with a translucent theme pack: buttons with artwork, cards, pill
   tabs, skeleton loading, tags, the approval banner and toasts, in light and
   dark.
